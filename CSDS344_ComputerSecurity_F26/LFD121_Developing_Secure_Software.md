# 3. Security Basics

* **Confidentiality** - no unauthorized read
* **Integrity** - no unauthorized  modification; cannot be swayed; firm adherence to a code.
* **Availability** - software continues working even while under attack

* From a security & privacy standpoint, the best approach to protecting personal data is to not collect  personal data at all

**Security Objectives**
* Confidentiality - identify info that shouldn't be publicly revealed; password stored using special algorithms.
* Integrity - identify info that only some people to modify, and who that is
* Availability - protect against data loss by designing software so its data is easily backed up, plan for regular backups; develop software that's not easily overwhelmed, can temporarily scale up to handle load, and recover quickly once an attack ends.
* Non-repudiation - Prove someone did something
* Identity & Authentication (I&A) - normally support two-factor authentication (2FA)
* Authorization - 
* Auditing/Logging - what info or events should you record? Examples include login, logouts, account creation, account deletion; what happened, when, which component performed the action, who caused it to happen.
